# Issues and Potential Pitfalls

**Deep Stream Similarity Grouper** (`stream_grouper.py`) and **True Duplicate Reviewer & Cleaner** (`json_46.py`) exhibit several technical edge cases, performance bottlenecks, and resource risks across both scripts.

---

## 1. Deep Stream Similarity Grouper Issues

* **Inefficient MD5 Hashing via Process Spawning:**
`get_stream_hash()` spawns an external `ffmpeg` process for every single video stream to output raw MD5 checksums. Spawning processes repeatedly in a large directory tree causes severe CPU overhead, slow runtime execution, and heavy process contention during parallel processing (`ThreadPoolExecutor`).
* **Unrestricted Symlink Traversal Risk:**
`analyze_file()` flags symlinks via `p.is_symlink()`, but `os.walk(..., followlinks=False)` doesn't completely guard against resolving symlinked directories if passed directly as target inputs, potentially leading to repeated scans or unintended path evaluations.
* **High Memory Usage on Large Media Libraries:**
`analyze_directory()` builds the entire file index into an in-memory database list (`database`) before categorizing or processing. On directories containing tens of thousands of media files, memory footprint scales linearly.
* **Race Conditions in File Quarantine:**
`main()` performs file existence checks (`while dest.exists():`) right before calling `shutil.move()`. If multi-threaded writes or external processes modify the quarantine directory concurrently, race conditions can occur.

## 2. True Duplicate Reviewer & Cleaner Issues (`json_46.py`)

* **Hardcoded Shared Memory Paths (Non-POSIX Crash):**
Paths like `/dev/shm/actions.json` and `/dev/shm/balance_order.json` are hardcoded. Running this script on Windows or non-Linux systems results in an unhandled `FileNotFoundError` or `PermissionError`.


* **External Subprocess Dependency Failure:**
`play_in_vlc()` calls `subprocess.run(["vlc", ...])` directly. If VLC is missing from the global system `PATH`, the script displays an error message, but the outer calling loop (`process_groups`) treats it as a failed attempt and proceeds without providing fallback media playback.


* **Sub-optimal Multi-select Parsing in Interactive Loop:**
In `process_groups()`, parsing multi-select user input (`sel.split(',')`) is wrapped in a generic `try...except Exception: pass` block. If a user enters out-of-bounds indices or invalid syntax, the error message `"Invalid input."` prints, but loop execution state tracking can become ambiguous.


* **Unsafe File Size Mutation in Group Validation:**
In `get_real_files()`, the script mutates dictionary elements (`item['size'] = stat.st_size`) inside the candidate list while iterating. In cases where shared state objects are referenced in memory across multiple tasks, side-effect mutations can introduce inconsistent file size states.

## 3. Cross-Script Compatibility & Logic Issues

| Issue | Source Script(s) | Impact |
| --- | --- | --- |
| **Conflicting Prime Selection Logic** | Both | `stream_grouper.py` selects prime files strictly by largest byte size (`max(group, key=...)`). `json_46.py` inverted prime rules for Super Groups (selecting `min()` byte size), leading to inconsistent handling when files cross between standard review and Super Group review workflows.

 |
| **Missing Schema Validation** | `json_46.py` | `json_46.py` assumes the output JSON report generated by `stream_grouper.py` follows a strict schema. If keys like `"True Duplicates"` are missing or malformed, `json_46.py` silently returns without detailed error messages.

 |
| **Quarantine Path Mismatch** | Both | `stream_grouper.py` moves files to `.stream_quarantine/`, while `json_46.py` looks for missing files inside a directory named `black_hole/`. Re-evaluating reports across both tools requires manually syncing these target destination names.

 |
